# 日程开发与验证

实现依据：综合工作台规格 §5、§8、§9。日程页提供月／周／日视图，默认周视图、周一开始；空白格新建、拖动改时间、拖动边缘改时长。表单支持标题、时间、全天、备注、6 色、全部重复预设和结束条件、提前提醒。新日程读取 `settings.default_event_remind`，未配置时不提醒；设置只影响之后新建的日程。

## 日历选型与许可证

使用 FullCalendar **6.1.21** 标准版：`@fullcalendar/react`、`core`、`daygrid`、`timegrid`、`interaction`。它已有成熟的月／周／日排版、重叠日程布局、拖动和缩放，减少自行维护日历交互的成本；重复规则仍由现有 `rrule` 数据层展开，再交给组件显示。

这些标准插件使用 [MIT 许可证](https://fullcalendar.io/license)，本项目未引入 Premium 插件。安装包内许可证原文保存在 `apps/desktop/public/calendar-licenses.txt`，会随 Vite 前端资源一起构建。React 适配包和标准插件各自的版权声明均按已安装包原文保留。

## 数据联动约定

- 工作台所有数据调用只在 `workbenches/general/src/api.ts`，经 `core/repositories` 访问 SQLite。日历组件不直接接触 Tauri 或 SQL。
- 修改／删除重复实例先选择「仅此次／此后全部／全部」，仓库调用原有 `editSeries`、`deleteSeries` 纯函数，再把变更集和提醒同步放进一个事务。拖动取消或保存失败会恢复原显示；过期快照会拒绝写入并提示刷新。
- 「全部」保留已有例外的内容和实际时间；「此后全部」迁移仍匹配新规则的未来例外，不再匹配的例外进入回收站。按日期拖动系列时，星期／月份日期跟随移动，拆分保留剩余 COUNT。
- 一个启用提前提醒的日程记录对应一条活跃 `source='event'` 提醒。标题、备注、时间、RRULE 与日程同步；取消提前提醒只软删除自动提醒。日程删除、恢复、内容清空会联动其关联提醒。之前独立删除的提醒不会被意外恢复。
- 重复提醒的 RRULE 原样同步；后续调度器应使用 `core/calendar/event-reminders.ts` 的 `expandEventReminders(events, reminders, range)`：先展开日程并应用 EXDATE／例外，再减提前量。这样每周日 00:05 提前 10 分钟会正确落在周六 23:55，不会因直接展开提醒 RRULE 而错一天。返回范围为提醒到期时间的半开区间。
- 当前只做数据联动。提醒页与系统通知在下一阶段接入，日程创建不会触发通知或开机自启提示。
- 定时日程以保存的 IANA 时区编辑，日历按本机时区显示；全天日程以日期保存与展示，结束日期包含当天，数据库内结束时间为次日午夜。夏令时缺失时间会提示重新选择，月末与闰日按 RRULE 跳过不存在的日期。
- 回收站「日程」组按联动删除组合并系列例外；恢复系列时一起恢复该组例外及提醒。单独删除的例外仍可单独恢复。所有清空操作保留墓碑，已发布迁移没有修改。

## 自动检查

在仓库根目录运行：

```powershell
pnpm install --frozen-lockfile
pnpm lint
pnpm typecheck
pnpm test
pnpm exec prettier . --check
pnpm --filter desktop tauri build --no-bundle
pnpm --filter desktop tauri dev
```

Vitest 使用内存 SQLite，覆盖自动提醒创建／同步／取消、三种重复实例修改与删除、例外迁移、联动删除恢复与清空、事务失败回滚、30 天边界，以及各重复预设、结束条件、月末、闰年、跨午夜提醒和夏令时日期。不会改动实际应用数据库。

## 手动测试步骤

1. 启动开发应用，打开「日程」。确认默认周视图，表头从周一到周日；切换月／日，再切回周；前后翻页和「今天」正常。
2. 点击周视图空白格，新建标题与备注，选择颜色，保存。拖到另一天／另一时间，再拖动上下边缘改变时长。关闭并重新运行应用，确认时间仍保留。
3. 新建全天日程，开始和结束选同一天。保存后应只占一天；跨多天日程包含结束当天。编辑表单的全天切换正常。
4. 分别创建每天、工作日、每周（多选星期）、每月（如 31 日）、每年（如 2 月 29 日）；检查永不／截止某日／共 N 次。月末与闰日不存在的日期会跳过。结束早于开始、0 次等输入应拒绝保存。
5. 新建每周重复 9 次的系列。拖动第二次，选择「仅此次」，确认只移动一次；再拖动普通实例选择「全部」，确认系列平移而已有例外实际时间保留；调整后续实例的时长选择「此后全部」，确认过去日程不变，未来按剩余次数生成。
6. 对重复实例点击「删除」，分别检查三种作用范围。取消弹窗不改变数据；确认后按范围消失，整组删除在「回收站 → 日程」出现。恢复后日程及关联提醒一起恢复；永久删除后不可恢复。
7. 设置「日程默认提前提醒」为提前 10 分钟，再新建日程，应自动选中该值。手动换成不提醒后保存，不能产生自动提醒。已有日程不因默认值变化而改变。
8. 提醒页尚未实现，可在开发控制台读取数据验证联动：执行 `const data = await (await import('/src/core/repositories/initialize.ts')).initializeDataLayer()`，再执行 `await data.reminders.list()`。启用提前 10 分钟后，自动提醒的 `source` 应为 `event`，`event_id` 对应该日程，`due_at` 比开始早 600000 毫秒；修改日程后同步，取消提醒后只在回收站查询中保留墓碑。
9. 切换浅／深主题，缩小到 900×600。日历时间网格和表单内容可滚动，取消／保存按钮保持可见。开发控制台不应出现 CSP、React 或数据库错误。

## 本次 Windows 实测记录

在独立应用标识 `com.royce.workbench.smoke.calendar` 的数据库中验证，未使用日常应用数据库。1200×800 和 900×600 两种窗口均已运行；检查了空白新建、拖动、缩放、三种修改范围、全天每年重复、默认提前量、日程回收站恢复及重启持久化。

三种删除和事务回滚通过同一原生应用的 API／SQLite 适配进行集成验证：3 次重复日程删除第二次后，「仅此次／此后全部／全部」分别剩 2／1／0 个日程和提醒实例；整组恢复重现 3 个实例；条件写入失败时前面的更新未提交。界面检查了删除范围弹窗并取消，未通过自动化点击实际删除确认。

未出现 CSP、React 或数据库错误，热更新正常。开发服务器有原先就存在的 `favicon.ico` 404，与本次日程功能无关。
