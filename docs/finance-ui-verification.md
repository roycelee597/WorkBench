# 金融指标工作台 F3 验证

本次在 Windows 上用浏览器和合成数据验证指标页。预览页使用和桌面端相同的图表、目录及设置解析，数据和设置存储由测试页提供。它不会启动 Tauri、运行金融引擎或访问正式版的数据库。

## 自动检查

在仓库根目录运行以下命令。Python 默认排除联网测试，Rust 的原生测试使用临时数据库和模拟子进程。

```powershell
pnpm lint
pnpm typecheck
pnpm test
pnpm exec prettier . --check
uv run --project engines/finance --locked pytest engines/finance/tests
cargo test --locked --manifest-path apps/desktop/src-tauri/Cargo.toml --lib finance::tests
```

本地通过 161 个 Vitest、58 个离线 pytest 和 6 个 Rust 测试。内存 SQLite 测试覆盖主指标与沪深300 叠加线的开市日缺行、已有显式空值和周末休市，较前一交易日的变化遇到缺值时也留空。图表测试验证日线和月均模式下沪深300 都按原交易日期定位并在缺口断开。占比轴随缩放范围调整时，超出数据范围的阈值仍可见。

## 手动复现

1. 在仓库根目录的 PowerShell 启动浏览器预览。只启动下面的 Vite 命令。

   ```powershell
   pnpm --filter desktop exec vite ../.. --config vite.config.ts --host 127.0.0.1 --port 1432 --strictPort
   ```

2. 用浏览器的 InPrivate／无痕窗口打开 [合成数据预览](http://127.0.0.1:1432/workbenches/finance/tests/preview.html)。目录应显示「交易拥挤」「市场宽度」「估值」三组及最新值。点「前 5% 成交额占比」，确认默认日线、3 年范围、沪深300 叠加开启，并显示一条 45% 默认虚线。再点「60 日新高占比」，检查当前值和说明区随指标变化。
3. 切换 1 年、3 年、5 年、全部，拖动底部缩放条的两端。前两个指标的全部数据从 2015 年起，占比纵轴根据可见数据和阈值自动缩放。返回前 5% 指标并点「月均」，应看到每月一值，当前月标注「本月至今」。
4. 用图例关闭沪深300 叠加，再刷新页面。叠加应仍关闭，刚才的指标、月均和范围应保留。用工具栏重新打开叠加，右侧指数点位轴应恢复。预览用浏览器本地存储模拟重启后的设置读取。
5. 打开「指数估值分位」，将显示范围切到「全部」。依次选择 5 年、10 年、全部估值窗口，对比曲线和最早非空点。合成数据的起点分别是 2009-07-07、2014-01-07 和 2008-01-01。切换创业板指、上证指数及 PB，再切到「原始值」。原始值从 2005 年起，左轴显示原始估值。切回分位后，当前值卡片同时显示分位与原始估值。
6. 在地址末尾加 `?theme=dark`，检查曲线、虚线、提示框与坐标轴在深色背景下可读。分别访问 `?empty=1`、`?empty=1&busy=1`、`?error=1`，确认暂无数据、正在准备和读取错误都有各自的提示。
7. 验证结束后，在预览服务器的 PowerShell 按 `Ctrl+C`。

F3 首轮在浏览器验证了以上交互。审查修复的开市日空点、叠加线、占比轴和日志行为通过了离线测试。

## F2 审查项

| 项目       | 实现与验证                                                                                                                                                                                                                        |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 测试连接   | 原生进程监控在 60 秒时发出取消信号，必要时再等最多 5 秒并终止进程树。Rust 用缩短的时限验证超时与取消流程。                                                                                                                        |
| 取消和退出 | 保留 PyInstaller 单文件包。引擎检查本次运行专用的取消文件，先尝试自行退出。每次运行把 `TEMP` 和 `TMP` 指向专用目录，原生端在进程结束后清理该目录。模拟子进程覆盖正常退出与目录回收，Python 离线测试覆盖取消后缓存快照和锁的状态。 |
| 引擎日志   | stderr 打码后写入 Tauri 应用日志目录的 `finance-engine.log`，按 1 MiB 轮转并保留一份 `.log.1`。临时目录清理失败会记录警告。Rust 测试覆盖归档脱敏、轮转和清理失败。                                                                |
| 等待子进程 | `collect()` 取出 child 后释放状态锁再等待，保留运行占用标记，使等待期间仍可处理取消。                                                                                                                                             |
| SQL 权限   | 移除 WebView 的 `sql:allow-load` 和 `sql:allow-close`。主窗口通过专用原生命令打开固定位置的只读金融缓存。Rust 测试确认缺失文件时不会创建文件，已有文件可读且写入失败。                                                            |

## Windows Tauri 与打包 sidecar 冒烟实测

2026-11-10，在确认正式版已从托盘退出后，先运行 `pnpm finance:engine` 打包 PyInstaller 单文件引擎，再用 `tauri dev --config` 启动标识为 `com.royce.workbench.f3-smoke` 的隔离实例。Tauri 的数据、日志、临时目录和系统凭据使用独立路径或命名空间。核对过 Tauri 实际启动的引擎与刚打包的引擎文件校验值一致。上游由本机模拟服务提供，使用五个交易日的合成行情和测试凭据。更新发起 18 个行情请求，测试连接发起 2 个请求。五个交易日不足以计算长窗口，更新按预期返回 `partial`，未执行完整回补。

| 检查                 | 实测结果                                                                                                                                                                                        |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 固定路径只读查询     | 空目录查询返回空且未创建库。写入合成库后从固定位置读出 44.2，`PRAGMA database_list` 返回隔离库路径。写表和 WebView 直接加载数据库均被拒绝。沪深300 叠加查询在缺失的周一返回空值，未给周末补点。 |
| 正常取消             | 在引擎等待重试时取消，约 0.66 秒后收到退出码 130。打包引擎的父子进程均退出。                                                                                                                    |
| 退出与强制结束       | 模拟上游保持连接阻塞。退出时先观察到取消文件，3.6 秒后 App 仍在等待，约 5.70 秒后 App 和两层引擎进程均退出。                                                                                    |
| 测试连接超时         | 连接持续阻塞时约 64.36 秒返回 `VERIFY_TIMEOUT`，包括约 60 秒监控时限和后续收尾。                                                                                                                |
| 临时目录回收         | 运行时观察到 PyInstaller 在本次运行专用 `TEMP` 中创建 `_MEI` 目录。正常完成、取消、连接超时和强制退出后，运行目录均已回收，隔离的外层 `TEMP` 也无 `_MEI` 残留。                                 |
| 日志脱敏与北交所提示 | 模拟北交所代码匹配，使用合成的凭据文本作为探针。中文日志可读，检测到脱敏标记，完整探针文本在日志中未出现，也没有疑似换码的前端事件。Windows 管道中的 stderr 已统一为 UTF-8。                    |

测试凭据已清除，测试实例已退出。实测前后正式版 `finance.db` 的 SHA-256 一致。WebView2 在退出时记录了一条窗口类注销诊断（1412），测试进程和提取目录均已回收。

## Vite 构建体积

同一台 Windows 机器上分别对 F2 的 `main` 和 F3 执行 `pnpm --filter desktop exec vite build`。首次加载大小按 `index.html` 引用的入口脚本和 `modulepreload` 脚本相加，gzip 逐文件压缩后相加。单位为十进制 kB。

| JavaScript       |                          F2 |                          F3 |
| ---------------- | --------------------------: | --------------------------: |
| 首次加载         | 1,029.6 kB（gzip 318.4 kB） | 1,032.9 kB（gzip 321.0 kB） |
| 金融图表独立分包 |                           — |   580.1 kB（gzip 193.6 kB） |

金融图表分包仅在打开金融工作台后加载。Vite 仍对超过 500 kB 的分包发出体积提示。
